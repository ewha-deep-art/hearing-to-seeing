# 파이프라인 설계

영상 입력부터 색상 자막 재생까지의 전체 흐름. 각 단계의 구현 상태와 미결 사항을 함께 표기한다.
미확정 결정 사항은 [TODO.md](TODO.md)를, 코드 구조는 [CLAUDE.md](../CLAUDE.md)를 참조한다.

**대상 범위: 유튜브 영화 클립, 20분 내외.**

| 표기 | 의미 |
|---|---|
| 🟢 | 구현 완료 |
| 🟡 | 부분 구현 |
| 🔴 | 미구현 |

## [1] 입력 🟡

| 입력 | 필수 | 용도 |
|---|---|---|
| 영상 파일 (사용자 업로드) | 필수 | **실제 처리 대상** |
| 유튜브 링크 | 필수 | [3] 영화·장면 식별용 메타데이터 |
| 유튜브 제목 | 필수 | 〃 |

링크·제목은 메타데이터일 뿐이며 **다운로드하지 않는다.**

내부적으로 **분석용 사본**(다운스케일 영상 + 16kHz mono wav)을 만들어 [2]·[4]에서 사용하고,
원본은 [9] 재생에만 쓴다.

> 구현: [`source.py`](../src/hearing_to_seeing/source.py) — `--title` / `--url` →
> [`MediaInfo`](../src/hearing_to_seeing/schema.py) 🟢
> 오디오 추출 🟢 ([`media.decode_audio`](../src/hearing_to_seeing/media.py)) /
> 영상 다운스케일 사본 🔴 / 업로드 UI는 [7]과 함께 구현 🔴

## [2] WhisperX (ASR + diarization) 🟢

분석용 wav로 ASR + forced alignment + diarization을 한 번에 수행.

**출력** — 단어 단위 엔트리 (`text`, `start`, `end`, `speaker`).
타임스탬프는 단어 단위, 화자는 세그먼트 단위로 부여된다.

> 구현: [`stt.py`](../src/hearing_to_seeing/stt.py) → [`Transcript`](../src/hearing_to_seeing/schema.py)

## [3] 영화·장면 식별 → RAG 검색 🔴

**a. 제목 파싱** — 유튜브 클립 제목은 정제가 필요하다 (LLM 1회).
```
"[4K] 기생충 명장면 모음 | 아들아 너는 계획이 다 있구나 #shorts"
        ↓
작품명 "기생충"  +  장면 힌트 "아들아 너는 계획이 다 있구나"
```

**b. 장면 특정** — 클립 한정의 가장 큰 이점.
```
영화 전체    등장인물 20명  → 매핑 후보 20개
클립 한 장면  등장인물 3명   → 매핑 후보 3개
```
제목의 장면 힌트와 transcript 대사로 장면을 좁히면 [5]의 난이도가 크게 내려간다.

**c. RAG 검색** — **배우가 아니라 극중 인물** 정보를 찾는다.
- 등장인물 목록 + 성격·역할·관계 텍스트
- 프로필 사진(레퍼런스) — best-effort. 없어도 파이프라인은 진행된다

> ⚠️ 인물 문서에 **의상 색 묘사는 거의 없다.** 성격·역할 위주이므로 색상 근거로는 약하며,
> 색의 1차 근거는 [4]e에서 화면에서 직접 얻는다.

## [4] 화자별 대표 증거자료 추출 🔴

**a. 후보 세그먼트 선정** — 길이 1.5초 이상, 화자 오버랩 없는 구간 우선

**b. 프레임 추출** — 각 후보의 중간 지점에서, 분석용 사본으로부터 얼굴 검출

**c. 얼굴 개수로 우선순위 분기**

| 얼굴 수 | 처리 |
|---|---|
| 1명 | ✅ 사진 채택 — 기본 케이스. 대부분 여기서 화자당 3~5개 확보 |
| 2명 | 두 얼굴만 남기기 |
| 3명 이상 | 후순위로 밀고 1~2명짜리 다른 세그먼트로 대체 |

**d. 얼굴 0명** (오프스크린 목소리 등) → 후보 제외, 다음 순위로 대체

**e. 의상 대표색 추출**
```
얼굴 박스  →  아래쪽 상체 영역 크롭  →  피부·배경 제외  →  대표색
```
- 상체 영역: 얼굴 박스 높이 기준 아래로 약 1~3배, 좌우 ±1배
- 피부색 제외, 배경은 중앙 가중치로 완화 (person segmentation은 후속 과제)
- LAB/OKLCH 공간에서 k-means → 최대 클러스터의 중심색
- **여러 후보 사진의 결과가 일치할수록 신뢰도 상승** (조명·장면 차이를 상쇄)
- ⚠️ **채도가 임계값 미만이면 "색 근거 없음"으로 표기한다.** 실사 영화는 무채색
  의상(검정·회색·남색 정장)이 흔하므로, 억지로 색을 뽑지 않고 [6]b의 2단계로 넘긴다

**[4]의 산출물은 두 곳에서 쓰인다:**
1. [5]b 비전 자동 대조의 입력
2. **[7] 확인 UI에서 사용자에게 보여줄 증거** ← 레퍼런스 사진 확보에 실패해도 이쪽은 유효

## [5] 화자 → 인물 매핑 🟡

**a. 텍스트 기반** 🔴 — 화자 대사 + RAG 인물 특징으로 후보 추론
- 호명 탐지(규칙 기반)로 앵커를 먼저 확보한 뒤, 그 제약 위에서 LLM 추론
- 존댓말 방향·가족 호칭·관계로 보강

**b. 비전 기반** 🔴 — [4]의 얼굴 사진 vs RAG 레퍼런스 사진
- 1차: 얼굴 임베딩 유사도 (싸다)
- 2차: 애매한 경우만 비전 LLM으로 재확인 (비싸다)
- ⚠️ 애니메이션·분장이 심한 경우 임베딩이 작동하지 않는다. 레퍼런스 사진이 없으면 생략

**c. 결합** 🔴 — a + b → 화자별 최종 인물 후보 + 통합 신뢰도

**d. 실패한 화자 처리** 🔴 — 단역·나레이션 등 주요 인물이 아닌 화자
- **저채도 그룹**으로 통일: `L 고정 · C 낮음 · Hue는 화자마다 다름`
- 주요 인물(고채도)과 구분되면서, 단역끼리도 서로 구분된다
- 🔴 **흰색(`&H00FFFFFF`)은 사용 불가** — `SecondaryColour`와 같아져 카라오케 필이
  보이지 않게 되고 싱크 효과가 사라진다

> **수동 매핑** 🟢 — `--speaker-map "SPEAKER_00=기택,SPEAKER_01=충숙"`
> ([`identity.py`](../src/hearing_to_seeing/design/identity.py)).
> 자동 경로의 대체재가 아니라, 자동 결과를 교정하는 수단이자 정확도 측정의 정답지다.
>
> 신뢰도 임계값 미만을 기각하고 폴백하는 로직 🟢
> ([`resolve_speakers()`](../src/hearing_to_seeing/design/speaker.py))

## [6] 색상 결정 🟡

### a. 색상 기준

```
색 = OKLCH(L 고정, C 최대, H 자유)
      L 고정 → 어떤 색을 골라도 가독성이 보장된다
      H 자유 → 팔레트 7색 제한이 사라진다

배정 = 선호 각도에 최대한 가깝게 + 화자 간 최소 각도 간격 강제
```

- **색맹 안전성은 고려하지 않는다** (표현력 우선). 필요하면 이후 별도 옵션으로 분리
- 주요 인물은 고채도, [5]d의 실패 화자는 저채도
- 매핑 실패·신뢰도 미달 화자에 대한 폴백은 반드시 존재해야 한다

> 팔레트 기반 배정·충돌 해소·폴백 🟢
> ([`assign_from_preferences()`](../src/hearing_to_seeing/design/speaker.py)).
> 색상환(OKLCH)으로의 교체가 남아 있다 🔴

### b. 색상 추출 근거 (인물당 1회 캐싱) 🔴

| 단계 | 근거 | 성격 |
|---|---|---|
| 1단계 | **[4]e 의상 대표색** | 화면에 근거가 있어 **사용자가 즉시 검증 가능** |
| 2단계 | RAG 성격·역할 (1단계가 무채색이거나 실패 시) | 상징색 — 깊지만 검증 불가 |
| 실패 | 근거 없음 | a의 폴백으로 넘김 |

1단계를 앞에 두는 이유: 목표가 "누가 말하는지 즉시 인식"이므로,
**화면과 자막이 서로를 설명하는 색**이 상징적으로 깊은 색보다 낫다.

전략은 색을 확정하지 않는다 — **선호(선호 hue 각도 + 가중치)만 내놓고**, 확정은 a가 한다.

## [7] 확인 UI 🔴

신뢰도에 따라 사용자 수고를 차등 적용한다.

| 신뢰도 | 처리 |
|---|---|
| 높음 | 가벼운 확인만 요청 |
| 중간·낮음 | 상세 검토 UI 노출 |

**상세 검토 화면**
```
[RAG 레퍼런스 사진 + 인물명]   vs   [영상 증거자료(사진/클립) + 추정 인물명]
```
- 인물명·색상 수정
- 화자 병합/분리 (diarization의 과분할·병합 오류 교정)

> 자동화가 전혀 없어도 [4]의 증거자료만 있으면 이 UI는 성립한다.
> 사용자가 사진을 보고 이름을 고르는 것만으로 매핑이 완성된다.

## [9] 재생 🟡

- **원본 업로드 영상을 그대로 재생** — 화질 저하 없음
- 분석용 사본은 내부 분석 전용이며 재생에 관여하지 않음
- 자막·색상은 오버레이로 표시

> 현재는 ASS 파일 생성 🟢 ([`ass.py`](../src/hearing_to_seeing/converter/ass.py)) +
> ffmpeg burn-in 미리보기 🟢 ([`render.py`](../src/web/render.py)).
> 원본 화질을 유지하는 실시간 오버레이는 웹에서 ASS를 렌더링해야 하며(JASSUB 등) 미구현 🔴

## 구현 순서

| # | 작업 | 외부 의존 | 완료 시점의 상태 |
|---|---|---|---|
| **0** | 스키마 + 전략 계층 + 배정 🟢 | 없음 | 색상 결정을 갈아끼울 수 있는 토대 |
| **1** | [5] 수동 매핑 `--speaker-map` 🟢 | 없음 | **파이프라인이 끝까지 동작.** 평가셋 확보 |
| **2** | [6]a OKLCH 색상환 + [5]d 저채도 그룹 | 없음 | 팔레트 7색 제한 해제 |
| **3** | [4] 증거자료 추출 (+ 의상색) | 얼굴검출 | [7]에 보여줄 재료 확보 |
| **4** | [7] 확인 UI | 없음 | **실용 도구 완성** — 자동화 0%여도 쓸 만함 |
| **5** | [3] RAG + [5]a 텍스트 추론 | LLM | 자동화 ~70% |
| **6** | [6]b 색상 추출 근거 | LLM | 색에 의미가 생김 |
| **7** | [5]b 비전 대조 | LLM + 비전 | 자동화 ~85% |
| **8** | [9] 웹 플레이어 | 없음 | 원본 화질 재생 |

**4번까지가 외부 API 없이 도달 가능한 지점**이며, 그 자체로 완결된 도구다.
5번 이후는 "동작하게 만드는" 작업이 아니라 "사용자 수고를 줄이는" 작업이다.

### 선행 과제

**테스트 영상** — 3번부터는 실제 영상 없이 개발·검증이 불가능하다.
20분 내외 유튜브 영화 클립 1개를 `data/input/`에 두고, `uv sync`로 전체 의존성을 설치해야 한다.

**평가셋** — [5]의 정확도를 측정할 정답지가 없으면 개선 여부를 알 수 없다.
1번의 수동 매핑 결과가 그대로 평가셋이 된다.
