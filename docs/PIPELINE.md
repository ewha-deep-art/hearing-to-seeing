# 화자 색상 파이프라인 (RAG)

작품 제목에서 등장인물을 찾아 화자마다 의미 있는 색을 입히는 단계.
`feature/rag-character-color-mapping` 브랜치의 설계를 현재 dev 구조에 맞춰 단순화해 옮긴 것이다.
구현은 [`design/speaker.py`](../src/hearing_to_seeing/design/speaker.py) 한 파일에 있고,
외부 호출은 [`knowledge/`](../src/hearing_to_seeing/knowledge/)(`llm.py`·`retrieve.py`·`prompts.py`)가 맡는다.

---

## 실행 흐름

```
pipeline.run(..., title=영상 제목)
  ├─ 원격 WhisperX STT ───────────────────────┐    ← 병렬
  └─ lookup_characters(title)                  │
       ① LLM: 클립 제목 → 작품명               │
       ② 위키백과·나무위키 검색 (모델 호출 없음) │
       ③ LLM: 문서 → 인물표 + 인물별 자막 색   │
                                               ↓
     assign_speaker_colors(transcript, 인물표)
       ④ LLM: 대사 + 호명 앵커 → 화자별 인물
       ⑤ 색상환 배정 → transcript.speaker_profiles
```

- LLM 호출은 클립당 3회. 모델은 `gemini-3.6-flash`, 429/503이면 `gemini-3.5-flash-lite`로 한 번 더 요청한다.
- `GEMINI_API_KEY`가 없거나 제목이 없으면 ①–④를 건너뛴다. 어느 단계든 실패하면 경고만 남기고 균등 배치로 진행한다 — 작업은 실패하지 않는다.
- 웹 작업([`jobs.py`](../src/web/jobs.py))은 영상 제목을 넘기기만 한다. CLI는 제목을 넘기지 않으므로 항상 균등 배치.

## 단계별 설명

**① 제목 → 작품명** — `"[4K] 기생충 명장면 모음 #shorts"` → `"기생충"`. 작품을 특정할 수 없으면 여기서 중단.

**② 검색** ([`retrieve.py`](../src/hearing_to_seeing/knowledge/retrieve.py)) — 위키백과 검색으로 문서를 특정하고,
나무위키(등장인물 절이 있는 유일한 출처, best-effort)와 위키백과 본문에서 등장인물 → 개요·줄거리 절만 글자 수 예산 안에서 잘라낸다.
아무것도 못 찾으면 모델에게 기억으로 답하게 하고 신뢰도를 낮추게 한다.

**③ 인물표 + 색** — 전체 인물을 한 번에 물어, 인물끼리 색상 계열이 겹치지 않게 한다.
인물마다 이름·호칭·주연/조연·역할·성격·관계와 함께 자막 색(sRGB hex)과 근거를 받는다:
실제 의상 색이 문서에 있고 무채색이 아니면 `costume`, 아니면 성격·역할의 상징색 `symbolic`.
코드는 hex에서 OKLCH hue만 취하고, 채도가 `ACHROMATIC_CHROMA`(0.06) 미만이면 선호 없음으로 둔다.

**④ 화자 → 인물** — 대사(앞부분 전체 + 나머지 균등 샘플링)와 인물표를 주고 화자별 `{인물 | null, 신뢰도, 근거}`를 받는다.
프롬프트에는 규칙으로 센 **호명 앵커**가 제약으로 들어간다: 이름·호칭을 부른 화자는 그 인물이 *아닐* 가능성이 높고,
`REPLY_WINDOW`(4초) 안에 대답한 화자는 그 인물*일* 가능성이 높다.

**⑤ 색상 배정** — 색 = OKLCH(L 고정 0.75, 채도는 hue별 최대치의 비율, H 자유).
- 신뢰도 `MIN_CONFIDENCE`(0.7) 이상으로 매칭된 화자는 인물의 hue에 최대한 가깝게, 고채도로.
  충돌하면 가중치(주연 1.0/조연 0.6 × costume 1.0/symbolic 0.7 × 색 신뢰도) 순으로 선호를 지키고,
  나머지는 `MIN_HUE_GAP`(40°)만큼 밀려난다.
- 매칭되지 않은 화자는 남은 가장 넓은 빈 곳에 **저채도**로 — "주요 인물이 아님"으로 읽힌다.
- 아무도 매칭되지 않으면 모든 화자가 고채도로 색상환에 균등 배치된다.
- 색맹 안전성은 고려하지 않는다 (표현력 우선).

## 결과 저장

`transcript.json`의 `speaker_profiles`:

```json
"SPEAKER_01": {"color": "&H0045A0F2", "name": "기택", "confidence": 0.9,
               "reason": "기택아 호명 직후 응답 / 색(symbolic): 가장의 따뜻한 주황"}
```

ASS 변환기와 웹 범례가 모두 여기서 색을 읽으므로 둘은 항상 일치한다. 인물표 자체는 저장하지 않는다 (한 번의 실행 안에서만 쓰인다).

## 미결 과제

- 확인 UI 🔴 — 인물명·색상 수정, 화자 병합/분리. 수동 매핑·저장된 매핑 재사용도 이때 필요해지면 다시 넣는다.
- 화면 기반 증거(얼굴·의상 색) 🔴.
- 임계값(`MIN_CONFIDENCE`)·밝기(`LIGHTNESS`)·채도 비율은 경험값 — 실제 영상에서 검증 필요.
- 병렬화 때문에 인물표 프롬프트에 대사 발췌가 들어가지 않는다 (장면 특정은 하지 않음).
