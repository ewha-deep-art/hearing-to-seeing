# Hearing to Seeing 서비스 기획서

---

## 1. 서비스 개요

**서비스명:** Hearing to Seeing

**한 줄 정의:**
청각장애인·난청인이 영상 속 대사의 화자, 발화 시점, 목소리 크기(강조)를 시각 정보로 온전히 인식할 수 있도록, 소리 데이터를 분석해 동적으로 표현되는 배리어프리 자막을 자동 생성하는 서비스

**기획 배경:**
기존 청각장애인용 자막(CC/SDH)은 대사를 텍스트로 옮기는 데 그쳐, 누가 말하는지·언제 강조되는지·목소리가 얼마나 큰지 같은 청각적 뉘앙스를 전달하지 못한다. 본 서비스는 오디오에서 추출 가능한 객관적 신호(화자 구분, 발화 타이밍, 음량)를 자막의 시각적 서식(색상, 채워짐 효과, 글자 크기)으로 변환하여, 텍스트만으로는 놓치는 정보를 보완하는 것을 목표로 한다.

---

## 2. 타겟 & Pain Point

**타겟 사용자**
- 청각장애인 / 난청인 (핵심 타겟)
- 배리어프리 자막을 제작해야 하는 유튜브 크리에이터, 영화·영상 제작자
- (부가) 자막을 텍스트로만 읽는 데 피로를 느끼는 비장애인 시청자

**Pain Point**
- 기존 CC 자막은 모든 대사가 동일한 스타일로 표시되어 **누가 말하는지 즉시 구분되지 않음**
- 대사와 발화 시점이 어긋나 보여 **어디를 말하고 있는지 따라가기 어려움**
- 목소리 크기·강세 같은 정보가 텍스트만으로는 전달되지 않아 **대사의 강조점을 놓치기 쉬움**
- 배리어프리 자막 제작 자체가 수작업 중심이라 **제작자 입장에서도 시간·비용 부담이 큼**

---

## 3. 핵심 가치제안 / 차별점

| 기존 자막(CC/SDH) | Hearing to Seeing |
|---|---|
| 화자 표기가 없거나 이름 텍스트로만 구분 | 화자별 **색상**으로 즉시 구분 |
| 자막 전체가 한 번에 표시/사라짐 | 발화 시점에 맞춰 **글자가 채워지는 효과(sync)**로 정확한 타이밍 전달 |
| 목소리 크기 정보 없음 | 음량에 따라 **글자 크기**가 변화하여 강조 표현 |
| 대부분 수작업 제작 | 오디오 파일 입력만으로 **자동 생성** |

즉, "무엇을 말했는가"뿐 아니라 "**누가**, "**언제**", "**얼마나 강하게**" 말했는가까지 시각적으로 전달하는 것이 차별점이다.

## 4. 주요 기능 명세

> 구현 범위: **화자 구분 / Synchronization / 음량 기반 글자 크기** 3가지로 한정한다. 감정 매핑, 음악·효과음 등 비언어적 소리 감지·표기 기능은 이번 범위에서 제외한다.

| 기능 | 설명 | 표현 방식 | 우선순위 | 필요 기술 |
|---|---|---|---|---|
| 화자 구분 (Attribution) | 화자가 바뀔 때마다 자막 색상을 다르게 표시 | 화자별 고정 색상 매핑 | 필수 | 화자 분리(Speaker Diarization) — WhisperX 기반 |
| 싱크 (Synchronization) | 실제 발화 시점에 맞춰 해당 부분의 자막 색이 채워지고, 글자가 살짝 위로 뜸 | 색 채우기(fill) 애니메이션 + 위치 이동 | 필수 | 단어(또는 어절) 단위 타임스탬프 |
| 크기 (음량 강조) | 목소리 크기(음량)에 비례해 글자 크기 조절 | 최대/최소 폰트 크기 범위 내 스케일링 | 필수 | 오디오 진폭(Amplitude) 추출 |

**기능별 처리 흐름**
1. 오디오 추출 → 화자 분리 + 단어 단위 STT (WhisperX)
2. 화자별 색상 매핑 규칙 적용 (색맹 팔레트 기준 단순 배정 등)
3. 단어별 타임스탬프 기준으로 sync 효과 타이밍 계산
4. 단어 구간별 음량(진폭) 추출 → 글자 크기 스케일 계산
5. 위 정보를 JSON으로 통합 생성 → ASS 자막 파일로 변환

## 5. 사용자 시나리오 (User Flow)

**제작자(또는 사용자) 관점**
1. 영상/음성 파일 업로드 (또는 링크 붙여넣기)
2. 자동 분석 진행 (화자 분리 · 타임스탬프 · 음량 추출)
3. 생성된 자막 미리보기 (영상에 자막 오버레이된 상태로 확인)
4. 필요 시 화자별 색상 등 간단한 옵션 조정
5. 자막 파일(ASS) 다운로드 또는 영상에 적용된 파일로 내보내기

**시청자(청각장애인) 관점**
1. 배리어프리 자막이 적용된 영상 재생
2. 화자가 바뀔 때 색상으로 즉시 인지
3. 대사가 진행되는 부분이 색으로 채워지며 정확한 발화 시점 파악
4. 목소리 크기에 따라 커지는 글자로 강조되는 대사 인지

## 6. 서비스 형태 / 구현 범위

**구현 형태 (검토 중, 택 1 또는 단계적 확장)**
- 웹사이트: 영상 파일 업로드 또는 링크 입력 → 자막 생성 → 다운로드/미리보기
- 크롬 확장 프로그램: 시청 중인 영상에 실시간으로 자막 오버레이 (추후 확장 검토)

**1차 구현 범위**
- 실시간 처리 아님 (사전 처리 방식)
- 음성 인식 기반 (화면/영상 인식은 범위 외)
- 기존 자막 유무와 무관하게 오디오로부터 새로 생성하는 방식(무에서 유 창조)을 우선함
- UI는 중간 발표(1차) 시점에는 제외, 이후 단계에서 웹사이트 형태로 구현

---

## 7. 화면 설계 (초안 단계)

> UI 구현은 중간 발표 이후 단계이므로, 현재는 자막 표현 자체에 대한 스케치 수준으로 정리한다.

- 자막 표시 예시: 화자 A(파랑)·화자 B(주황) 등 색상 구분 + 발화 중인 단어 색 채우기 + 강조 구간 글자 확대
- 업로드 화면: 파일 업로드 / 링크 입력 두 가지 방식 지원 예정
- 결과 화면: 원본 영상 + 생성된 자막 오버레이 미리보기, 다운로드 버튼

*(추후 와이어프레임 이미지로 보완 예정)*

## 8. 기술 아키텍처 요약

```
오디오/영상 입력
   ↓
STT + 화자 분리 (WhisperX)
   ↓
JSON 생성 (화자, 텍스트, 시작/종료 시간, 단어 단위 타임스탬프, 음량)
   ↓
서식 규칙 적용 (화자별 색상 / sync 효과 / 음량→크기 매핑)
   ↓
JSON → ASS 변환
   ↓
자막이 적용된 영상 출력
```

- **화자 분리·STT:** WhisperX (심슨/미생/왕과 사는 남자 등 테스트 결과 비교를 통해 3개 후보 중 최종 채택 — 상세 비교는 별도 기술 로그 참조)
- **타임스탬프:** 단어(어절) 단위 강제 정렬(forced alignment)로 ±50ms 수준 정밀도 확보
- **음량 추출:** 오디오 진폭 분석 → 글자 크기 스케일링에 활용
- **자막 포맷:** 1순위 ASS(고급 서식·애니메이션 지원), 2순위 VTT

> 상세 기술 비교(WhisperX vs Whisper+Pyannote, 화자분리 정확도 테스트 등)는 별도의 기술 구현 문서에 정리하고, 본 기획서에는 결론과 아키텍처만 반영한다.

| 리스크 | 내용 | 대응방안 |
