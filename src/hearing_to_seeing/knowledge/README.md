# LLM 사용 (Gemini)

파이프라인이 언어 모델을 부르는 곳과, 각 호출이 지금 어떻게 구현돼 있는지 정리한 문서.
모델 호출은 모두 이 폴더를 거친다.

| 파일 | 역할 |
|------|------|
| [`llm.py`](llm.py) | Gemini 호출 창구 `ask()` 하나. 프롬프트(+ 영상/음성) → JSON 스키마에 맞는 dict |
| [`prompts.py`](prompts.py) | 질문 네 가지의 (SYSTEM, PROMPT, SCHEMA) |
| [`retrieve.py`](retrieve.py) | 위키백과·나무위키 문서 가져오기 (모델 호출 없음) |

호출하는 쪽은 [`pipeline.py`](../pipeline.py)(작품·인물표·화자 → 인물, 색 배정)와 [`review.py`](../review.py)(영상 검토)다.
결과 색은 중간 JSON의 `speaker_profiles`에 `#RRGGBB`로 저장되고, [`design/speaker.py`](../design/speaker.py)는 이를 ASS 색으로 바꾸기만 한다.

---

## 실행 흐름

```
pipeline.run(wav, ..., title=영상 제목, media_path=원본 영상)
  ├─ 원격 WhisperX STT (패스 여러 개) ─────────────┐    ← 병렬
  └─ lookup_characters(title)                     │
       ① LLM: 클립 제목 → 작품명                  │
       ② 위키백과·나무위키 검색 (모델 호출 없음)    │
       ③ LLM: 문서 → 인물표 + 인물별 자막 색      │
                                                  ↓
     review_transcript(패스들, 인물표, 영상)          [review.py]
       ④ LLM + 영상: 발화별 말하는 인물 + 엇갈린 단어 고르기
                                                  ↓
     correct_names(인물표의 이름·호칭)                  [stt.py, 규칙 기반]
     assign_speaker_colors(transcript, 인물표, ④의 이름)
       ⑤ (④가 실패했을 때만) LLM: 대사 + 호명 앵커 → 화자별 인물
       ⑥ 색상환 배정 → transcript.speaker_profiles
```

## 호출 요약

| | 질문 (`prompts.py`) | 호출 위치 | 모델 | 폴백 | 언제 |
|---|---|---|---|---|---|
| ① | `TITLE_*` | `pipeline.lookup_characters` | `H2S_LLM_MODEL` (기본 `gemini-3.6-flash`) | `gemini-3.5-flash-lite` | 키 + 제목 |
| ③ | `CAST_*` | `pipeline.lookup_characters` | 〃 | 〃 | ①이 작품을 특정했을 때 |
| ④ | `REVIEW_*` | `review.review_transcript` | `H2S_REVIEW_MODEL` (기본 `gemini-3.5-flash`) | 없음 | 키가 있으면 항상 (클립 10분 이하) |
| ⑤ | `SPEAKERS_*` | `pipeline.identify_speakers` | `H2S_LLM_MODEL` | `gemini-3.5-flash-lite` | 인물표가 있는데 ④가 실패했을 때 |

입력 조건별로 실제로 일어나는 일:

| 조건 | LLM 호출 | 결과 |
|------|---------|------|
| `GEMINI_API_KEY` 없음 | 0회 | 화자 분리 라벨 + 다수결 대사, 색은 균등 배치 |
| 키 있음, 제목 없음 (CLI) | ④ 1회 (화자만) | ④의 이름으로 화자 라벨을 다시 나눔. 인물표가 없으므로 이름은 표시되지 않고 색은 균등 배치 |
| 키 있음, 제목 있음 (웹) | ①③④ 3회, ④ 실패 시 ⑤ 추가 4회 | 인물 이름 + 인물 색 |
| ①이 작품을 특정 못 함 | ①④ 2회 | 제목 없음과 같음 |

- 웹 작업([`jobs.py`](../../web/jobs.py))은 영상 제목과 원본 영상을 넘긴다. CLI는 제목을 넘기지 않으므로 ①③⑤는 돌지 않고, `--video`를 주면 ④가 영상을 본다(없으면 WAV를 듣는다).
- 어느 단계든 실패하면 경고만 남기고 진행한다(④ 실패 → 다수결 대사와 ⑤, 그 밖 → 균등 배치). 작업은 실패하지 않는다.
- 무료 티어 하루 한도는 모델당 약 20회다. ④가 다른 모델을 쓰는 이유 중 하나가 한도를 따로 쓰기 위해서다.

## `llm.ask()` 공통 동작

- 응답은 `response_json_schema`로 강제하므로 파싱은 실패하지 않는다. 출력 한도(`MAX_TOKENS` 16,000, thinking 포함)에서 잘리면 예외.
- 요청 타임아웃 180초. 5xx는 SDK가 최대 4번 재시도(2–20초 간격)한다. 503이 오래 이어지면 이것만으로 수 분이 걸릴 수 있다.
- 429(한도)·503(과부하)이면 `FALLBACK_MODEL`(`gemini-3.5-flash-lite`)로 한 번 더 요청한다. `fallback=False`면 바로 예외.
- `media_path`가 있으면 파일을 업로드하고(영상은 처리 완료까지 대기), 저해상도(`MEDIA_RESOLUTION_LOW`)로 프롬프트 앞에 붙인 뒤, 끝나면 삭제한다. 미리 올린 파일(`llm.upload`)은 `media`로 넘긴다. 영상 검토는 업로드에 약 10초가 걸려서 `pipeline.run`이 STT와 동시에 올려 둔다(`review.upload`).
- `configured()`로 키가 있는지 먼저 확인해, 키가 없으면 호출 자체를 하지 않는다.

## 단계별 설명

**① 제목 → 작품명** — `"[4K] 기생충 명장면 모음 #shorts"` → `"기생충"`. 작품을 특정할 수 없으면 `null`을 받고 ①–③을 중단한다(인물표 없음).

**② 검색** ([`retrieve.py`](retrieve.py)) — 위키백과 검색으로 문서를 특정하고,
나무위키(등장인물 절이 있는 유일한 출처, best-effort)와 위키백과 본문에서 등장인물 → 개요·줄거리 절만 글자 수 예산(나무위키 24,000자, 위키백과 8,000자) 안에서 잘라낸다.
아무것도 못 찾으면 `NO_DOCUMENTS`를 넣어 모델이 기억으로 답하고 색 신뢰도를 낮추게 한다.

**③ 인물표 + 색** — 전체 인물을 한 번에 물어, 인물끼리 색상 계열이 겹치지 않게 한다.
인물마다 이름·호칭·주연/조연·역할·성격·관계와 함께 자막 색(sRGB hex), 근거, 색 신뢰도를 받는다:
실제 의상 색이 문서에 있고 무채색이 아니면 `costume`, 아니면 성격·역할의 상징색 `symbolic`.
코드는 hex에서 OKLCH hue만 취하고, 채도가 `ACHROMATIC_CHROMA`(0.06) 미만이면 선호 없음으로 둔다.
인물표의 이름·호칭은 Whisper가 잘못 받아 적은 이름을 고치는 데도 쓰인다(`stt.correct_names`, 모델 호출 없음).

**④ 영상 검토** ([`review.py`](../review.py)) — 여러 STT 패스를 다수결로 합친 대사를 발화 단위(라벨 변경, 0.5초 휴지, 문장 끝)로 자르고,
패스끼리 엇갈린 자리를 `⟨dN @t: 1) … ×k | 2) … ×k⟩`로 표시해(패스 하나만 단어를 빠뜨리거나 더한 4–1 자리는 빼고, `t`는 읽은 패스들의 중앙값) 영상(없으면 음성)과 함께 보낸다. 모델은 두 가지를 **고르기만** 한다:
- 발화마다 말하는 인물 — 화면에서 입이 움직이는 인물 기준. 인물표의 이름을 쓰고, 이름 없는 인물은 `손님1`, `손님2` ….
- 엇갈린 자리마다 다수결(1번)이 아닌 다른 읽기가 분명히 들릴 때만 그 번호. 새 텍스트는 쓰지 못하므로 단어 타이밍은 패스의 것을 그대로 쓴다.

답의 이름은 화자 분리 라벨을 대체한다: 이름마다 말한 시간이 가장 많이 겹치는 라벨을 1:1로 가져가고, 남는 이름은 새 라벨을 받는다.
이 이름이 ⑥에 그대로 넘어가므로(신뢰도 1.0) ⑤를 부르지 않는다.

- `temperature=0`, 폴백 없음 — flash-lite는 엇갈린 자리마다 엉뚱한 선택지를 골라 쓸 수 없다.
- 인물표가 없으면 단어 고르기는 빼고 화자만 묻고, thinking을 `low`로 낮춘다(전체 thinking은 30,000 토큰을 넘겨 답이 잘렸다).
- 영어 프롬프트를 쓴다 — 같은 지시를 한국어로 주면 다수결을 더 자주, 더 자주 틀리게 뒤집었다.
- 10분(`MAX_SECONDS`)보다 긴 클립은 보내지 않는다.
- 측정과 근거: [STT_TUNING.md 4차](../../../docs/STT_TUNING.md#4차-영상-검토-gemini).

**⑤ 화자 → 인물 (대사 기반, ④ 실패 시)** — 대사(앞부분 9,000자의 절반은 그대로 + 나머지 균등 샘플링)와 인물표를 주고 화자별 `{인물 | null, 신뢰도, 근거}`를 받는다.
단어 3개 미만인 화자는 묻지 않는다. 프롬프트에는 규칙으로 센 **호명 앵커**가 제약으로 들어간다:
이름·호칭을 부른 화자는 그 인물이 *아닐* 가능성이 높고, `REPLY_WINDOW`(4초) 안에 대답한 화자는 그 인물*일* 가능성이 높다.

**⑥ 색상 배정** (모델 호출 없음) — 색 = OKLCH(L 고정 0.75, 채도는 hue별 최대치의 비율, H 자유).
- 신뢰도 `MIN_CONFIDENCE`(0.7) 이상으로 매칭된 화자는 인물의 hue에 최대한 가깝게, 고채도(95%)로.
  충돌하면 가중치(주연 1.0/조연 0.6 × costume 1.0/symbolic 0.7 × 색 신뢰도) 순으로 선호를 지키고,
  나머지는 `MIN_HUE_GAP`(40°)만큼 밀려난다.
- 매칭되지 않은 화자(④의 `손님1` 등 포함)는 남은 가장 넓은 빈 곳에 **저채도**(32%)로 — "주요 인물이 아님"으로 읽힌다.
- 아무도 매칭되지 않으면 모든 화자가 고채도로 색상환에 균등 배치된다.
- 색맹 안전성은 고려하지 않는다 (표현력 우선).

## 결과 저장

`transcript.json`의 `speaker_profiles`:

```json
"SPEAKER_01": {"color": "#F2A045", "name": "기택", "confidence": 0.9,
               "reason": "기택아 호명 직후 응답 / 색(symbolic): 가장의 따뜻한 주황"}
```

④로 정해진 화자는 `confidence` 1.0, 근거는 `"영상 검토에서 말하는 인물로 확인"`이다.
ASS 변환기와 웹 범례가 모두 여기서 색을 읽으므로 둘은 항상 일치한다. 인물표 자체는 저장하지 않는다 (한 번의 실행 안에서만 쓰인다).

## 파이프라인 밖: 측정 스크립트

[`scripts/stt_eval.py`](../../../scripts/stt_eval.py)도 Gemini를 쓰지만 `llm.ask()`를 거치지 않고 SDK를 직접 부른다(한도·과부하 시 최대 40번까지 기다렸다 재시도). 앱 동작에는 영향이 없다.
- `refs` — STT 점수용 참조 대본. `tr`/`tp`는 `gemini-3.5-transcribe`(클립 전체 / 45초 조각), `pw`는 Flash 모델(기본 `gemini-3.8-flash`)이 조각마다 화자·시간까지 적는다.
- `review` — 앱의 `review.review_transcript`를 그대로 불러 모델·영상/음성·인물표 유무를 바꿔 가며 비교한다.

자세한 사용법은 [STT_TUNING.md](../../../docs/STT_TUNING.md)의 재현 절.

## 미결 과제

- 확인 UI 🔴 — 인물명·색상 수정, 화자 병합/분리. 수동 매핑·저장된 매핑 재사용도 이때 필요해지면 다시 넣는다.
- 화면 기반 색 증거(의상 색) 🔴 — ④는 화자만 영상으로 확인하고, 색은 여전히 문서(③)에서 온다.
- 임계값(`MIN_CONFIDENCE`)·밝기(`LIGHTNESS`)·채도 비율은 경험값 — 실제 영상에서 검증 필요.
- 병렬화 때문에 인물표 프롬프트에 대사 발췌가 들어가지 않는다 (장면 특정은 하지 않음).
- CLI에는 제목 옵션이 없어 인물 색을 쓸 수 없다.
